**Breaking:** Release 7.0.0 rounds up M29–M34, the move from one engineering crew in `scripts/` to a modular team framework; migration: widen a code pack's `pack.toml` `framework` range to include 7.x (for example `">=6.0.0, <8.0.0"`), since bootstrap and upgrade refuse a pack whose range excludes the installed release, then follow `docs/guides/migration.md`. M29 wrote the specs and contracts (the team spec, the generic actions contract, specs in the essential doc set and baseline metrics). M30 and M31 decoupled the code and moved it into modules along four independent axes, roles, connectors, environments and harnesses, plus `core/`, `cli/`, `profiles/`, `packs/` and `dev/`, shipped in 6.0.0 with code packs (`pack.toml`, `mdstack pack list`, `mdstack pack test`). M32 took the team beyond engineering: role classes with owner-facing seats, internal staff and one team head (the coordinator, Ash, holds the `cto` seat and now signs as CTO), C-suite seat placeholders, on-demand role lifecycles that scale to zero, role routines, a core memory layer in git, `mdstack action` as the terminal binding of the generic actions, and connectors that now include knowledge, with Notion as the first. M33 renamed the CLI to `mdstack` and added `mdstack migrate --rename-to` with an owner-run repository rename runbook. M34 consolidated the public docs (module READMEs, reading paths, the four-axes glossary) and added getting-started, connector, pack author and migration guides. The `crew` CLI name and the 6.0.0 `scripts/` path shims still ship in 7.0.0; their removal is a follow-up.
