Release 7.6.0: session-runtime and org-pack parity (M40). A session crew now runs the same pipeline as tmux. `mdstack upgrade` runs on a session profile (#1541), `mdstack bootstrap` passes its `briefs` self-test there (#1540), the session synthesizer brief carries gate-status reporting and verdict portability again (#1539), session profiles accept `runtime.options.release_delegation` (#1542), and an async land binding lands through `mdstack land request` (#1351). `runtime.options.session_backend = "hosted"` runs workers as hosted sessions created through a control plane (#1052), a session crew can run always-on triage, including on a non-GitHub tracker (#1404), and `runtime.options.role_runtime` adopts a runtime one role at a time (#1055). Hosts: an inventory host can carry its DNS name as `[hosts.<name>] address` (#1034), `mdstack host prepare` supports a checkout made by a declared command (#1035), and `mdstack connect <alias> [session]` opens the owner's shell on a host (#1036). For org packs: the release bundle ships `scripts/changelog-cut.py` (#1033), `precheck-scope` classifies removed and renamed paths (#1345), and `resolve` prints a `pack.toml` pack's version again (#1350). Crew runtime: `mdstack doctor` and `mdstack up` preflight the launcher sandbox and `mdstack restart` relaunches the coordinator in place (#1544), route wakes the coordinator on a milestone-closing or release-cut merge (#1559), role posts end with a usage line of time, tokens and model (#1557), and the tmux synthesizer is a long-lived lead in window 1 that takes land events straight from route (#1569). No breaking changes; upgrade a 7.5.0 install with `mdstack upgrade --version v7.6.0`, after which the watcher or the next `mdstack up` starts the synthesizer lead, and `mdstack spawn synthesizer` refuses.
