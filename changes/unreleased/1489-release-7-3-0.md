Release 7.3.0 brings remote role sessions and the local multi-device lab (M20.1, with M25.1 integration work). Remote role sessions: `mdstack spawn` places each run with a `[hosts]` inventory (#207), and a run placed on a role host starts, is killed, restarted and stopped there with the worktree guards intact (#345). Its status lines wake the coordinator through a pulled mirror, and `mdstack send` and `acked` reach it through the host (#346). A partitioned host's runs turn `unreachable` without losing their claims, reconcile when the host returns, and can be abandoned only by the owner, leaving a tombstone (#347). `mdstack attach` and `mdstack logs` reach remote runs (#348). The local multi-device lab: a pinned base image (#1430), Docker role-host setup and teardown (lab C, #1357), `mdstack runner` scenarios with failure injection over the hardened SSH call (lab F, #1360), a per-run evidence record marked simulated (lab G, #1361) and an opt-in `lab` CI job (lab H, #1362), on top of the host OS adapters that shipped in 7.2.0 (#1358, #1359). Integration follow-ups: the attended owner-channel sleep run driver (#1463) and the A30 remote-builder journey on the lab for #209 (#1442), with the M25.1 evidence ledger that indexes #716 and audits #157 and #158 (#1445); #209, #716 and #158 stay open for their real-device closures. Crew safety: a bare `tmux kill-*` run from a worker or lead window can no longer reach the crew's server (#1475). The main-red fix scopes the attended-run test's fake clock to its own module (#1479). Also in this release: a lone surviving train member collapses to a direct land and a `train-merge` survey gate (#1425), triage clusters (#1298), A19 installed-adapter smoke and declared-operation replay (#1439, #1443), the A31 campaign-history report (#1462), `crew-install.py` on Python 3.11.0 to 3.11.3 (#1447), the triage P0 re-fire fix (#1093), a reason for an unreadable `mdstack feedback` answer (#1096), a route test flake (#1453) and the Pi, Cursor and Muse `BUSY`/`COMPOSER` gap (#1459). No breaking changes; upgrade a 7.2.0 install with `mdstack upgrade --version v7.3.0`. A role host authorized before this release keeps working, but `mdstack attach` to it needs its key line rewritten as `restrict,pty` (re-run the lab host's `authorize`, or edit `authorized_keys` per the multi-device role-host runbook).
