Landing is bound to the repo `--project` selects (team §9.5). `mdstack train` records the selected project's `context` in its train and delegation records and, before any clone, branch, record, push, CI dispatch, merge or cleanup, reads first, then writes: every record and delegation an action names and the predecessor train each builds on, every member qualifier (`<owner>/<name>#<n>`) and the full lookup of every change the action can write for (build and delegate members; for land, wait, bisect, route and close every member, each dropped member route merges up and a pending merge record's change), which land, route and build then act on; `train land` also reads train CI, the default branch and the member's gate (change, landing control issue, hold dependencies) before the pending merge record or any other write. One foreign or unreadable read refuses the whole action with nothing written (an unresolvable hold, control issue, CI or gate view no longer closes the train or records a pause), so another repo's verdict, merge-ok or train result at the same number and SHA never counts and never closes the train; `train check` reports such a read as a blocked gate. Async land and stack intents record the `context`, `land request|resume|done`, `land stack|stack-done` and resume refuse an intent naming another repo before any read, request or drop, and `land stack --stack` takes `<owner>/<name>#<n>:<sha>` members, refusing the whole stack when one names another repo. `land-lock` records the repo's `context` and the acquiring window in `locks/merge.pid` and refuses a record naming another repo before any cleanup, signal or removal; each repo keeps its own lock. The tmux synthesizer lead brief gains a team-land paragraph. In a one-repo config a record written before this change, without `context`, stays the selected repo's; gate satisfaction, actors, fail-open paths and markers are unchanged.
