# Crew PR metrics

A thin, refreshable record of cycle time and review rounds for closed crew PRs,
so later harness changes can show before and after on velocity and quality. It
is a snapshot table, not a dashboard: no charts, no live API.

Files:

- `prs.md`: the table, with a header stating lookback, repos and generation time
  (UTC).
- `prs.csv`: the same rows as CSV.
- **Dated snapshot.** The committed `prs.md` and `prs.csv` were generated
  2026-10-29 and predate the columns from `flavor` onward in [Fields](#fields).
  Read them as that day's snapshot, not current data; regenerating them is an
  operational follow-up.
- Generated by [`scripts/metrics-refresh.py`](../../scripts/metrics-refresh.py).
  Do not edit the two data files by hand.
- [baseline-m25.md](baseline-m25.md): median pipeline latencies and per-PR
  counts over M25, the baseline before the reorganization (#1220). See
  [Baseline report](#baseline-report).
- [a31-campaign-report.md](a31-campaign-report.md): the A31 campaign-history
  report over M25's actual PR and decision records (#1462). See
  [Campaign-history report](#campaign-history-report).
- [decisions.md](decisions.md): how these numbers trip a harness issue and
  pause new `M*` feature work.
  [`scripts/metrics-decide.py`](../../scripts/metrics-decide.py) reads
  `prs.csv` and prints the verdict.

## Crew PR definition

A closed PR (merged or closed unmerged) whose `closed_at` falls in the lookback
and that either has a hidden `crew:v1 role=builder` marker in its body or has
any `crew:` label.

## Fields

| Field | Type | How derived |
|---|---|---|
| `repo` | `<owner>/<repo>` | The repo queried |
| `pr` | integer | PR number |
| `state` | `merged` or `closed` | `merged` when the PR has a merge time, else `closed` (unmerged) |
| `opened_at` | UTC timestamp | PR `created_at` |
| `merged_at` | UTC timestamp | PR `merged_at`; blank if not merged |
| `open_to_merge_min` | integer minutes | `merged_at` minus `opened_at`, rounded; blank if not merged |
| `ci_fix_rounds` | integer | Distinct builder `pass=ci-fix` markers (distinct by `round` and `sha`) in review bodies |
| `builder_fix_rounds` | integer | Distinct builder `pass=fix` markers (distinct by `round` and `sha`) in review bodies |
| `verdicts` | integer | Distinct reviewer-validator `pass=verdict` markers in review bodies (Vera verdict count) |
| `changes_verdicts` | integer | Of those, the ones with `verdict=changes` |
| `flavor` | string or blank | Optional `flavor=` on the latest reviewer-validator `pass=verdict` marker at the PR head; blank when absent, never inferred from the project default |
| `escaped_defects` | integer | Distinct bug issues or intake cards whose body has a whole-line `Escaped from: <owner>/<repo>#<pr>`; repeated references on one issue count once |
| `engine_runs` | integer or blank | Recorded builder runs plus review and validation runs; see below. Blank means no attribution was found |
| `precheck` | `recorded` or `unrecorded` | `recorded` when a whole-line builder `pass=precheck` marker occurs in the PR body or a review; otherwise `unrecorded` |
| `reopened` | `reopened` or blank | `reopened` if the issue events show a `reopened` event; blank means none seen (unknown) |
| `lane` | `crew`, `express` or `solo` | `crew:express` or `crew:solo` on the PR when fetched (after close); otherwise `crew` |
| `selfgate_mode` | `same`, `different` or blank | `mode=` on the latest builder `pass=selfgate` marker in review bodies; blank when none |
| `selfgate_reviews` | integer | Sum of `reviews=` over distinct builder `pass=selfgate` markers (distinct by `sha`; the latest per `sha` counts) |
| `selfgate_findings` | integer | Sum of `findings=` over the same markers |
| `dispatch_to_merge_min` | integer minutes | `merged_at` minus the author time of the PR's first commit with an `Engine:` trailer, rounded; blank if not merged or no such commit |
| `ci_red_rounds` | integer | Distinct commits on the PR with a red required check (GraphQL `isRequired` for the PR; conclusion or state `FAILURE`, `ERROR`, `TIMED_OUT`, `CANCELLED`, `STARTUP_FAILURE` or `ACTION_REQUIRED`), for every lane. A commit with no required check configured counts any red check, as crew's own CI read does |
| `merge_ups` | integer | Distinct `pass=merge-up` markers in review bodies, any role (distinct by `sha`, so a builder note and its ack count once) |
| `reverted` | `reverted` or blank | A merged PR in the same repo whose title or body says `Revert <owner>/<repo>#<pr>` or `Reverts #<pr>`, merged within 72 hours after this PR's merge |

Only the hidden whole-line `<!-- crew:v1 ... -->` marker is parsed, as defined
in [../protocol.md](../protocol.md) section 4. Prose or inline code that
mentions a marker is ignored. `Escaped from:` and commit `Engine:` trailers
are whole-line inputs too.

Builder runs count distinct `Engine:` trailer values within each commit range
ending at a verdict, fix or ci-fix head, plus the remaining commits. Repeated
trailers in that range count once; `Engine: none (pure merge-up, plain git)`
is excluded. Review and validation count separately by `(round, sha, pass)`
when that section has an engine field or a `Reviewed by` / `Validated by`
signature (also `Review engine:` / `Validation engine:`). Repeated posts count
once; an ack or a final verdict marker adds no engine run. This is a recorded
run proxy, not token usage, quota percent or a billing estimate.

At triage the coordinator adds `Escaped from:` to bug issues and intake cards
only for defects found after the source PR merged. It omits unknown sources
and pre-merge soft findings. The search covers accessible issues across repos
so an intake card in the control-plane repo can cite a product PR. Counts
include open and closed defects without a defect-date cutoff: `--since`
filters the PR's close date only, so a late-discovered defect still counts.

## Pre-review check comparison

The generated `prs.md` rollup splits each repo by `precheck`, reporting:

- **Rounds per PR:** total distinct verdicts divided by closed crew PR count.
- **Request-changes rate:** total `changes_verdicts` divided by total verdicts,
  as a percentage (a verdict rate, not the fraction of PRs with any change request).
- **PR-to-merge time:** mean `open_to_merge_min` for merged PRs only.

The table includes PR, verdict and merged-PR counts; an empty denominator is
`n/a`. CSV retains the per-PR counts, times and cohort for further analysis.
No gate threshold changes. A recorded marker measures reported precheck use,
including failed or N/A steps and checks first recorded in a later fix; it
does not independently prove the check ran. An unrecorded PR may have had the
profile switch disabled, skipped reporting or predated the feature, so this
comparison cannot establish enabled versus disabled configuration or causality.
Markerless verdict histories still contribute zero rounds, as in the raw table.

## Refresh

The script uses the `gh` CLI for read-only API calls and relies on gh's own
authentication (a `GH_TOKEN` environment variable or a `gh auth login`
session). It never reads, stores or prints a token. Five calls per PR (details, commits, reviews,
events and one GraphQL check-rollup query) plus three searches per repo (closed PRs, escaped
defects and merged revert PRs).

From the repo root:

```sh
python3 scripts/metrics-refresh.py                         # last 14 days
python3 scripts/metrics-refresh.py --days 30
python3 scripts/metrics-refresh.py --since 2026-10-26      # since a milestone close
python3 scripts/metrics-refresh.py --repo <owner>/<repo>   # repeatable
```

Options: `--repo` (repeatable; default the pilot repos `mw-ding/eng-crew` and
`mw-ding/agentconnect`), `--since YYYY-MM-DD` (by closed date; overrides
`--days`), `--days N` (default 14), `--out-dir` (default `docs/metrics`). Rows
are sorted by repo, then PR number. Each refresh overwrites both files, so to
keep an earlier window, pick a `--since` that covers it. For "since the previous
milestone close", pass that close date to `--since` (M2 closed 2026-10-26).

Offline self-test of the parsing logic (no network):

```sh
python3 dev/tests/scripts/test-metrics-refresh.py
```

## Baseline report

[`scripts/metrics-baseline.py`](../../scripts/metrics-baseline.py) reports,
for one repo over a window of closed dates, the median of each metric below
and a per-PR table. It selects crew PRs as [above](#crew-pr-definition) and
reuses `metrics-refresh.py`'s `gh` calls and marker parsing. Measurement only:
it changes no crew behaviour, gate or threshold.

| Metric | How derived |
|---|---|
| Issue to PR | Closing issue (first `Closes`, `Fixes` or `Resolves #<n>` line in the PR body) created to PR opened |
| PR to first verdict | PR opened to the earliest review carrying a reviewer-validator `pass=verdict` marker |
| Verdict to land | Latest verdict review submitted at or before the merge, to `merged_at`; merged PRs only |
| Handoff ack latency | PR opened to the earliest reviewer-validator `pass=ack` review submitted at or before the first verdict (the builder-to-reviewer handoff; later merge-up acks are ignored) |
| Rounds per PR | `verdicts`, as in [Fields](#fields) |
| Defects caught per PR | `changes_verdicts`: verdicts that requested changes, from review or validation. The report also prints the total |
| Engine cost per PR | `engine_runs`, as in [Fields](#fields): a recorded run proxy, not tokens or billing |

A PR with no value for a metric (no closing issue, no verdict, unmerged, no
recorded engine run) is left out of that median; the `PRs` column is the
count used. With `--milestone N` only PRs whose closing issue is in milestone
number `N` are kept. Four calls per PR (closing issue, details, reviews,
commits) plus one search.

The committed [baseline-m25.md](baseline-m25.md) was generated with:

```sh
python3 scripts/metrics-baseline.py --repo mw-ding/eng-crew \
  --since 2026-11-03 --until 2026-11-07 --milestone 38 \
  --out docs/metrics/baseline-m25.md
```

It covers 44 of M25's 46 issues; the other two (#782, #805) are trackers
closed without a PR. Issue to PR counts from issue creation, so it includes
time an issue waited in the backlog or on hold, not only build time. Offline
self-test: `python3 dev/tests/scripts/test-metrics-baseline.py`.

## Campaign-history report

[`scripts/campaign-report.py`](../../scripts/campaign-report.py) is campaign
scenario A31's report from actual records, not the scenario's fake history.
`capture` keeps the crew PRs whose closing issue is in one milestone and that
closed in the window, stores each as a `metrics-refresh.py` row with its
closing issue, and adds the decision log's `[Ash/decision]` comments created
in the window. `report` renders the stored file with no network call: per lane
(standard `crew`, express, solo) the PR, merged and verdict counts with their
denominators, the timing medians, and the owner decision records. An empty
lane prints `n/a`. Blank fields, an empty decision log and token counts are
listed under Missing data, never estimated.

The committed [a31-campaign-report.md](a31-campaign-report.md) was rendered
from the recorded capture in `dev/tests/scripts/fixtures/campaign/a31/`:

```sh
python3 scripts/campaign-report.py capture --repo mw-ding/mdstack --milestone 38 \
  --since 2026-11-03 --until 2026-11-07 --decision-log 985 \
  --out dev/tests/scripts/fixtures/campaign/a31/records-m25.json
python3 scripts/campaign-report.py report \
  --records dev/tests/scripts/fixtures/campaign/a31/records-m25.json \
  --out docs/metrics/a31-campaign-report.md
```

Its PR, verdict and changes-verdict counts match [baseline-m25.md](baseline-m25.md),
captured separately over the same window. Decision records cover every
milestone in the window, not only M25, and the report does not classify them.
Offline self-test: `python3 dev/tests/scripts/test-campaign-report.py`.

## Known limits

- Escaped defects require explicit whole-line links in issue bodies. Links in
  comments and unrecorded defects are not counted; zero means none recorded.
- Engine runs are a lower bound when trailers, section signatures or historical
  heads are missing (for example after a rewrite). Commits are limited by the
  GitHub PR commits API to 250; unrecorded restarts are not visible.
- Older PRs with no `flavor=` at head remain blank until the optional verdict
  field from the flavor protocol work lands.
- Rounds come from markers in review bodies only. A marker posted as a plain
  issue comment is not counted, and a PR without markers shows zeros.
- The search API caps at 1000 results per query; shorten the lookback if a repo
  exceeds that.
- The express-lane columns ([../express-lane.md](../express-lane.md#metric-columns))
  only record data; the lane comparison is out of scope. `ci_red_rounds` sees
  only the last 250 commits and 100 checks per commit, and falls back to all
  checks on a repo without required checks. `reverted` needs a `Revert(s) [<owner>/<repo>]#<pr>` reference (the
  GitHub revert button's body) and a revert merged within the lookback.
- The refresh is not run in CI.
